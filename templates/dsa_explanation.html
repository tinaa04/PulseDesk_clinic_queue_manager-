THE ENGINE UNDER THE HOOD

Real data structures.
Understandable logic.

PulseDesk uses Python's heap operations in an actual scheduling module, with SQLite as persistent storage.

01234
01

Min-heap priority queue

The queue key is (priority rank, appointment eligibility, sequence number). Smaller values are served first. Acute/emergency is a staff-assigned scheduling category and does not replace emergency protocols.

Insert / remove O(log n)
02

FIFO tie-breaking

Each visit gets an increasing sequence number. Patients with equal effective scheduling priority retain registration order unless staff changes priority.

Tie-break O(1)
03

Hash-map lookup

The in-memory queue uses a dictionary keyed by visit ID for active-entry access. Patient identity lookup is handled with SQLite queries on patient ID, name and phone.

Dictionary lookup O(1) average
04

Search complexity

Queue positions are found by ordering active heap entries. Patient search currently uses parameterized SQL LIKE matching; without an additional index this is a scan of matching patient rows.

Name search O(n) worst case
05

Persistence & rebuild

Patients, visits, histories, appointments and activity are stored in SQLite. On each queue refresh, eligible waiting visits are rebuilt from database records, so browser state is not authoritative.

Queue rebuild O(n log n)
06

Priority changes

The queue manager updates the priority and calls heapify to restore the heap property. The demo module exposes this operation for tests and future staff-only controls.

Reheapify O(n) with heapify
